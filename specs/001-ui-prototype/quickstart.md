# Quickstart: 畫面與流程原型

本文件說明如何執行 001 並驗證它符合 spec。介面與資料見 [contracts/](contracts/) 與 [data-model.md](data-model.md)，這裡不重複。

## 前置需求

- Node.js 24 LTS（repo 根目錄的 `.nvmrc`）
- 第一次執行端對端測試前，安裝 Playwright 的 Chromium
- 001 不需要 Google 帳號、金鑰或 `.env`

## 安裝與啟動

在 repo 根目錄執行：

```bash
npm install
```

```bash
npx playwright install chromium
```

```bash
npm run dev
```

開啟終端機顯示的本機網址，每個頁面都應看到「模擬模式」標示。要同時展示老師與學生，開多個分頁；每個分頁的模擬狀態各自獨立，重新整理即回到首頁與「沒有活動」。

## 自動化測試

| 指令 | 內容 | 預期結果 |
| --- | --- | --- |
| `npm run typecheck` | `shared/`、`frontend/` 的 TypeScript 檢查 | 沒有錯誤 |
| `npm run lint` | ESLint，含「頁面與元件不得引用 `services/mock`」規則（原則 III） | 沒有錯誤 |
| `npm test` | Vitest：`tests/unit`、`tests/component` | 全部通過 |
| `npm run test:e2e` | Playwright：`tests/e2e` | 全部通過 |

implement 階段每完成一個 Phase，回報上述指令與結果（原則 VIII）。

## 驗證情境

每個情境對應 spec 的 User Story 與 Success Criteria；自動化測試與人工驗證都依此執行。人工驗證結果記錄在 `specs/001-ui-prototype/manual-verification.md`（日期、驗證者、情境、結果、問題）。

| 編號 | 情境 | 操作 | 預期結果 | 對應 |
| --- | --- | --- | --- | --- |
| Q1 | 選擇身分 | 首頁點「我是學生」；回首頁點「我是老師」 | 分別進入選組頁與登入頁 | US1、SC-005 |
| Q2 | 登入兩種結果 | 登入頁點「用 Google 登入」，依序選兩個模擬帳號選項 | 選「模擬老師帳號」進入挑選學習單頁並顯示帳號；選「取消」留在登入頁並顯示「已取消登入」 | US1 AC-3、AC-4 |
| Q3 | 匯入三份學習單 | 依序挑選三份模擬學習單；對「表頭錯誤範例」按「重新讀取」；關閉選擇器 | 依 M2 進入確認辨識結果頁或找不到表頭頁；關閉時留在原頁 | US2 AC-1–5 |
| Q4 | 活動設定、驗證失敗與取消活動 | 調整組數；點「模擬：驗證失敗」後按「建立活動」；再按一次；在控制台點「取消活動」，先按「繼續準備」，再點一次並按「確定取消活動」 | 第一次在組數欄位旁顯示「模擬：驗證失敗」；第二次進入控制台・準備中；「繼續準備」留在控制台，活動不變；「確定取消活動」進入挑選學習單頁，可以重新挑選並建立活動 | US2 AC-7–12、US5 AC-8 |

| Q6 | 寫回 | 以兩份可辨識的學習單各走一次到寫回 | 按「寫回」後確認視窗不關閉：「題組＋單題範本」在視窗內顯示寫回成功與格數；「單題範本」在視窗內顯示寫回失敗與原因；按鈕只剩「關閉」，關閉後結果頁保留一行寫回狀態 | US3 AC-10–14；FR-042 |
| Q7 | 學生被接受、被拒絕與組員送出 | 學生加入組別，推進到作答：一次送出後點「模擬：接受」；一次送出後點「模擬：不接受」；一次在作答頁點「模擬：同組組員送出」 | 接受時直接進入本題結果頁（最後一題為全部結果頁）；不接受時停在等待判定頁顯示「老師沒有接受本組的答案」且不能再送出；組員送出時切換到等待判定頁並顯示組員的答案 | US4、SC-006；FR-055、FR-056、FR-056a |

| Q13 | 加入組別時的目的頁 | 在選組頁先推進到不同階段再加入組別：準備中、搶答中、本題已結束、已結束 | 依序進入等待開放頁、作答頁、本題結果頁（本組沒有送出）、全部結果頁（本組搶到 0 題）。「同組組員已送出時加入」在模擬模式不會發生，以元件測試驗證 | FR-056a；spec「階段推動的切換」；SC-002 |
