# Quickstart: 搶答活動

**Feature**: `002-buzzer-session` | 驗證本功能是否完成的操作手冊。實作細節見 `tasks.md`。

## 前置條件

- Node.js 24 LTS；專案根目錄執行過 `npm install`
- 001 已完成，或用測試替身提供一份 `QuestionSet`（題組範本：4 題，第 1、2 題為題組）

## 自動化測試

```bash
npm test -w packages/server -- buzz session
npm run test:load -w packages/server     # 壓力測試：200 連線、1 秒 1,000 筆，重複 20 次
```

壓力測試的通過條件（SC-006、SC-007）：遺失 0 筆、序號重複或空號 0 次、各處順位不一致 0 次；回覆延遲 p95 ≤ 1 秒、最長 ≤ 2 秒。

## 手動驗證情境

啟動 `npm run dev`。開 1 個老師分頁、3 個學生分頁（第 1、3、5 組），老師建立活動時設定 6 組、每題 30 秒。

| # | 操作 | 預期結果 | 對應 |
| --- | --- | --- | --- |
| 1 | 學生選組後停在等待畫面 | 顯示「等老師開放第 1 題」，不能作答 | AC-02 |
| 2 | 老師按「開放第 1 題」 | 所有分頁 1 秒內切到第 1 題，倒數一致 | AC-03、SC-001、SC-008 |
| 3 | 第 3 組只填（1）就送出 | 被拒絕，說明（2）還沒填 | AC-10 |
| 4 | 第 1、3 組幾乎同時送出 | 老師控制台出現 #1、#2，序號不同；學生只看到「本組已送出」 | AC-08、AC-09、AC-17 |
| 5 | 檢查第 5 組分頁收到的 WebSocket 訊息（瀏覽器開發者工具） | 不含其他組的答案、數量或順位 | AC-16、SC-003 |
| 6 | 等倒數歸零 | 所有分頁顯示第 1 題結束與成功組別；之後送出被拒絕 | AC-04、AC-13、AC-32 |
| 7 | 學生在第 2 題進行中重新整理 | 回到原組別、看到第 2 題與剩餘秒數 | AC-05 |
| 8 | 學生分頁用開發者工具送 `teacher:openNext` | 回 `FORBIDDEN` | AC-06 |
| 9 | 結束最後一題 | 活動變為已結束，結果出現在所有分頁 | AC-30 |
| 10 | 開啟公平模式（3 秒）重做情境 4，讓已搶到 2 題的組先送 | 結束時判給搶到較少題的組 | AC-20 |

手動驗證結果記到 `specs/002-buzzer-session/manual-verification.md`（原則 VIII）。
