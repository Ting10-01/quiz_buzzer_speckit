# Quickstart: 活動與階段同步

**Feature**: `004-buzzer-session` | 驗證 004 是否完成的操作手冊。實作細節見 `tasks.md`。

## 前置條件

- Node.js 24 LTS；專案根目錄執行過 `npm install`。
- 002（老師登入）與 003（匯入學習單）已完成。自動化測試不需要：伺服器測試以 002 的 `buildApp` 建立，並以替身取代 002 的老師驗證與 003 的 `ImportStore`。
- 手動驗證需要 002 的環境變數（`GOOGLE_CLIENT_ID` 等，由使用者自行設定），以及一份可匯入的學習單（例如「題組＋單題範本」，4 題）。

## 自動化測試

```bash
npm test -w server -- activity                  # 單元與整合測試
npm test -w frontend -- HttpActivityService     # 前端服務的單元測試
npx playwright test -c frontend/playwright.config.ts activity-sync   # 端對端：1 個老師 + 3 個學生分頁
npm run test:load:activity -w server            # 壓力測試：201 個連線，重複 20 次
```

壓力測試的通過條件（SC-002、NFR-01、NFR-02）：階段改變超過 1 秒才送達的連線 0 個；版本號倒退或重複 0 次；結束時與伺服器狀態不同的連線 0 個；200 個加入每個都恰好一次 ack，各組人數總和 200。

## 手動驗證情境

執行 `npm run dev`。開 1 個老師分頁、3 個學生分頁（同一個瀏覽器）。老師登入並匯入 4 題的學習單。

| # | 操作 | 預期結果 | 對應 |
| --- | --- | --- | --- |
| 1 | 學生分頁先進入選組頁 | 顯示「目前沒有活動」 | AC-15 |
| 2 | 老師進入活動設定頁 | 組數預設 6；按「−」到 2 時「−」不可用；按「+」到 20 時「+」不可用 | AC-01、AC-02 |
| 3 | 老師設 4 組、建立活動 | 老師進入控制台・準備中；學生選組頁 1 秒內列出第 1–4 組 | AC-03、AC-15 |
| 4 | 學生 A、B 加入第 3 組，學生 C 加入第 1 組 | 控制台 1 秒內顯示第 3 組 2 人、第 1 組 1 人 | AC-09、AC-10 |
| 5 | 學生 C 按「選錯組別？重新選擇」改加入第 2 組 | 第 1 組 0 人、第 2 組 1 人 | AC-11 |
| 6 | 老師「修改設定」改成 2 組 | 被拒絕：「第 3 組已有學生加入，組數不能少於 3」 | AC-05 |
| 7 | 老師開放第 1 題 | 所有分頁 1 秒內切到第 1 題；學生在作答頁 | AC-17、SC-001 |
| 8 | 學生 A 重新整理，從首頁進入選組頁選第 1 組 | 被拒絕：「第 1 題開放後不能換組，你在第 3 組」 | AC-12、AC-14 |
| 9 | 學生 A 改選第 3 組 | 回到第 3 組作答頁；控制台第 3 組仍是 2 人 | AC-14 |
| 10 | 老師結束第 1 題 | 所有分頁 1 秒內顯示第 1 題已結束，學生切到本題結果頁 | AC-18 |
| 11 | 老師重新整理，從首頁登入 | 直接回到控制台・本題已結束（第 1 題）；學生分頁沒有變化 | AC-25、AC-26、SC-005 |
| 12 | 老師開放並結束第 2、3、4 題 | 每次同步切換；結束第 4 題後老師進入結果頁、學生進入全部結果頁 | AC-19、AC-20、SC-004 |
| 13 | 在學生分頁的開發者工具查看 WebSocket 訊息 | `spreadsheet.id` 為空字串；沒有任何作答資料；只有 `websocket` 連線，沒有 `polling` 請求 | AC-16、REQ-ACT-20、SC-003 |
| 14 | 在學生分頁的開發者工具以 `fetch` 呼叫 `POST /api/activity/questions/1/open`（不帶老師憑證） | `401`，活動不變 | AC-07、SC-006 |
