# 子功能拆分

本文件記錄系統拆成哪些子功能，以及各子功能涵蓋 `docs/assignment.md` 的哪些需求。開發流程、分支與 commit 規則見 `CLAUDE.md`、`CONTRIBUTING.md` 與 constitution，本文件不重複。

## 1. 拆分原則

- 以使用者看得到、能單獨展示的能力為單位，不以技術分層。
- 彼此依賴才能運作的需求放在同一個子功能。
- 各子功能的大小接近。

## 3. 跨子功能的需求分工

| 需求 | 子功能 | 負責的部分 |
| --- | --- | --- |
| R1 | 001 | 首頁的身分選擇；學生直接進入選組頁，不需要登入；老師進入登入頁（只有畫面） |
| R1 | 002 | 登入頁的登入行為；登入後才能使用老師功能；伺服器端拒絕未登入者使用老師功能的請求 |
| R4 | 005 | 作答狀況：老師依送出順序檢視並判定各組答案 |
| R4 | 006 | 搶答結果 |
| R9 | 005 | 一題作答期間，學生看不到其他組別的作答狀況 |
| R9 | 006 | 一題結束後才解除限制，公布該題結果 |
| E1 | 003 | 解析題組結構 |
| E1 | 005 | 搶答時整組一次送出所有小題 |

### 3.1 名詞定義

- **一題**：以題號為單位。題組算一題，其中的小題與題組整組一起作答、送出。
- **題數（R2.1）**：以題號計算，題組算一題。以題組範本為例是 4 題。
- **期間、結束後（R3、R4、R9）**：都以一題為單位。老師逐題開啟與結束搶答。

### 3.2 R10 與 E4

學生送出後，老師依送出順序判定各組答案（R4 的作答狀況）。老師只能判定最早一筆還沒判定的答案，選擇接受或不接受；不接受就輪到下一組。第一個被老師接受的組別為搶答成功，因此 R10「最快的組別」仍然成立。每組每題只能送出一次，不被接受的組別這一題不能再送出。老師接受後，該題自動結束並公布結果。此部分屬於 005。

### 3.3 頁面的歸屬

- 001 定義所有頁面（老師端與學生端）、按鈕與頁面流程，以及使用者點擊造成的頁面切換。
- 按鈕的行為透過介面呼叫，001 提供模擬實作。後面的子功能以新增真正的實作取代模擬實作，不修改 001 的畫面。
- 需要修改畫面、按鈕或流程時，先修改 001 的 spec。
- 001 的模擬實作依固定規則產生結果，讓各流程都能展示（例如學生送出答案時決定接受或不接受，讓接受與不接受的流程都能展示）。具體規則在 001 的 spec 決定。
- 活動階段改變時自動切換學生頁面，屬於 004。

## 4. 跨子功能已決定的事項

| 子功能 | 事項 | 決定 |
| --- | --- | --- |
| 001 | 模擬實作的具體規則 | 在 001 的 spec 決定 |
| 004 | 同一組有多位學生 | 允許。任一組員送出就代表全組（由 005 執行） |
| 005 | 被拒絕的組別能否重送 | 不能，每組每題只能送出一次 |
| 005 | 老師接受後題目是否自動結束 | 是。最後一題被接受時，活動一併結束（由 004 處理） |
| 004 | 結束最後一題時 | 活動直接結束，不另外經過該題的「本題已結束」。006 的寫回只在活動結束後才能使用 |
| 006 | 公布結果的範圍 | 一題結束時，所有人看到該題搶答成功的組別、答案與送出組數。整輪結束後，公開每一題所有組別的答案、順位與判定 |
